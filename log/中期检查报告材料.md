## 一、项目概述与研究背景

### 1.1 研究目标

本项目旨在深入研究 Google OpenXLA 编译器的核心架构，重点聚焦于 XLA 以 CPU 为后端的 HLO（High-Level Optimizer）优化流程，并探索将 XLA 编译器迁移部署到国产飞腾派（Phytium）处理器硬件平台的可行性方案。

### 1.2 XLA 编译器简介

XLA（Accelerated Linear Algebra，加速线性代数）是 OpenXLA 项目中的核心机器学习编译器，具有以下显著特点：

| 特性 | 说明 |
|------|------|
| **多框架支持** | 支持 PyTorch、TensorFlow、JAX 等主流 ML 框架 |
| **多后端支持** | 支持 GPU、CPU 以及 ML 加速器等多种硬件平台 |
| **模块化设计** | 提供可插拔的后端基础设施，便于扩展新平台 |
| **性能优化** | 通过生产级验证的优化 Pass 实现性能最大化 |

## 三、XLA 编译流程架构分析

### 3.1 整体编译流程

根据我们对 XLA 源码的分析，其编译流程可分为以下 7 个主要阶段：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        XLA Compilation Pipeline                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌──────────────────────┐                                                 │
│  │   Input Sources       │  ──── TensorFlow / JAX / PyTorch              │
│  └──────────┬───────────┘                                                 │
│             ↓                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ Stage 1: Frontend (Parsing/Converting)                               │  │
│  │   将前端输入转换为 XLA HLO IR                                        │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│             ↓                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ Stage 2-3: HLO Optimization Passes                                   │  │
│  │   执行硬件无关的优化：代数简化、重塑移动、卷积折叠等                   │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│             ↓                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ Stage 4: Layout Assignment                                          │  │
│  │   分配具体硬件的内存布局（Row-major/Column-major）                    │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│             ↓                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ Stage 5: Buffer Assignment                                          │  │
│  │   分配和复用内存缓冲区                                               │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│             ↓                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ Stage 6: Scheduling                                                 │  │
│  │   确定指令执行顺序，生成调度表                                        │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│             ↓                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ Stage 7: Code Generation (HLO → LLVM IR → Target Code)              │  │
│  │   生成 LLVM IR 并编译为目标硬件代码                                  │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│             ↓                                                               │
│                              ┌─────────────────────┐                       │
│                              │   Executable        │                       │
│                              └─────────────────────┘                       │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 HLO IR 核心数据结构

我们在源码分析中发现，`HloComputation` 类是 XLA HLO IR 中表示计算单元的核心类：

```cpp
// HloModule (父容器)
│
├── entry_computation_: HloComputation*    // 入口计算体
│
├── HloComputation (计算单元)
│   ├── root_instruction_: HloInstruction*     // 计算输出
│   ├── param_instructions_: vector<...>         // 输入参数
│   ├── instructions_: HloInstructionList        // 所有指令
│   └── callee_computations_: btree_map<...>     // 被调用的子计算
```

**关键设计特点**：
- 指令之间没有显式的全序关系，由数据依赖和控制依赖决定偏序关系
- 支持嵌套计算（nested computation），例如 `kMap` 指令可包含子计算
- 两阶段删除机制确保 Pass 执行期间指令指针稳定性

## 五、XLA CPU 后端 HLO 优化 Pass 研究

### 5.1 Stage 3 Pass 概述

在 `CpuCompiler::RunHloPassesThroughLayoutAssn` 中，Stage 3 阶段包含 21 个核心 Pass，负责将复杂 HLO 指令分解为简单标准指令：

| 类别 | Pass 数量 | 代表性 Pass |
|------|-----------|-------------|
| **分解类** | 6 | TopkDecomposer, DotDecomposer, AllToAllDecomposer |
| **内联类** | 2 | MapInliner, CallInliner |
| **转换类** | 4 | OperandUpcaster, ResultCaster, ConditionalToSelect |
| **展开类** | 5 | RngExpander, CholeskyExpander, TriangularSolveExpander |
| **归一化类** | 4 | BatchDotSimplification, ComparisonExpander |

### 5.2 重点 Pass 深度解析

#### 3.2.1 TopkDecomposer（最重要）

**功能**：将复杂的 TopK 操作分解为基本操作的组合

```hlo
// 优化前：复杂操作
ROOT topk = (f32[10], s32[10]) topk(p0), k=10, largest=true

// 优化后：分解为 6 个基本操作
%iota = s32[100] iota(), iota_dimension=0           // 1. 生成索引
%sort = (f32[100], s32[100]) sort(p0, %iota), ... // 2. 排序
%values = f32[100] get-tuple-element(%sort), index=0 // 3. 提取值
%top_values = f32[10] slice(%values), slice={[0:10]} // 4. 取前k个
%indices = s32[100] get-tuple-element(%sort), index=1 // 5. 提取索引
%top_indices = s32[10] slice(%indices), slice={[0:10]} // 6. 取前k个索引
ROOT %tuple = (f32[10], s32[10]) tuple(%top_values, %top_indices)
```

#### 3.2.2 DotDecomposer（结构规范化）

**功能**：将非规范 Dot 转换为标准 2D Dot + Reshape

```hlo
// 优化前：非规范 3D Dot
dot = f32[64,63,512] dot(lhs, rhs)

// 优化后：规范结构
%reshape_lhs = f32[4032, 512] reshape(lhs)
%reshape_rhs = f32[512, 512] reshape(rhs)
%dot = f32[4032, 512] dot(%reshape_lhs, %reshape_rhs)
ROOT %reshape_out = f32[64,63,512] reshape(%dot)
```

#### 3.2.3 MapInliner（抽象消除）

**功能**：将 Map 操作内联为直接操作，类比函数内联

```hlo
// 优化前
%map = f32[100] map(a, b), to_apply=%max_fn

// 优化后：Map 被消除，直接使用 maximum
%maximum = f32[100] maximum(a, b)
```

#### 3.2.4 OperandUpcaster（精度管理）

**功能**：自动插入精度转换，bf16/f16 → f32

```hlo
// 优化前
ROOT dot = f32[8,8] dot(%p0_bf16, %p1_bf16)

// 优化后：自动提升精度
%c0 = f32[8,8] convert(%p0_bf16)    // bf16 → f32
%c1 = f32[8,8] convert(%p1_bf16)    // bf16 → f32
ROOT dot = f32[8,8] dot(%c0, %c1)   // f32 计算
```

### 6.2 hlo-opt 工具详解

`hlo-opt` 是 XLA 源码中 `opt_main.cc` 实现的工具，用于从一个 HLO 文件读取模块，针对指定平台运行优化或转换。

#### 5.2.1 关键 Flags 说明

| Flag | 说明 | 默认值 | 例子 |
|------|------|--------|------|
| `--platform=<PLATFORM>` | 目标平台 | `transforms` | `gpu`, `cpu`, `transforms` |
| `--format=<FORMAT>` | 输入格式 | 根据文件扩展名推断 | `hlo`, `pb`, `pbtxt` |
| `--stage=<STAGE>` | 输出阶段 | `hlo` | `hlo`, `llvm`, `ptx`, `buffer-assignment` |
| `-o <FILE>` | 输出文件 | `-` (stdout) | `-o output.txt` |
| `--passes=<PASSES>` | 运行指定 passes | （无） | `--passes=constant-folding,dce` |
| `--split-input-file` | 按 `// -----` 分隔符切分 | 无 | `--split-input-file` |
| `--list-stages` | 列出支持的所有阶段 | （无） | `--list-stages` |
| `--list-passes` | 列出支持的所有 passes | （无） | `--list-passes` |
| `--emit-proto` | 输出 proto 格式（不优化） | 无 | `--emit-proto` |
| `--debug_options_file=<FILE>` | 调试选项配置文件 | （无） | `--debug_options_file=debug.pb` |

#### 5.2.2 实际使用范例

```bash
# 1. 最简单的范例：对 HLO 文件运行标准优化
bazel run //xla/tools:hlo-opt -- /path/to/module.hlo

# 2. 指定 Pass 序列
bazel run //xla/tools:hlo-opt -- --passes=constant-folding,dce,hoist-constants /path/to/module.hlo

# 3. 列出某平台支持的所有 passes
bazel run //xla/tools:hlo-opt -- --platform=gpu --list-passes

# 4. 输出 LLVM IR
bazel run //xla/tools:hlo-opt -- --platform=gpu --stage=llvm -o /tmp/output.ll /path/to/module.hlo

# 5. 处理多个 HLO 模块
bazel run //xla/tools:hlo-opt -- --split-input-file --platform=gpu /path/to/multi_modules.hlo
```

## 八、HLO 代码实验与优化分析

### 8.1 HLO 代码表示法

HLO 中的张量类型表示法：

```hlo
f32[10,32]{1,0}
 ↓   ↓     ↓
数据  形状  布局
类型
```

- **f32**：32位浮点数数据类型
- **[10,32]**：10×32 的矩阵形状
- **{1,0}**：内存布局，第1维最快变化（行优先/Row-major）

### 8.2 神经网络 HLO 优化示例

#### 优化前（原始 HLO）：
```
ENTRY main {
  %p0 = f32[10,32]{1,0} parameter(0)     // 输入
  %p1 = f32[32,64]{1,0} parameter(1)     // 权重
  %dot.6 = f32[10,64]{1,0} dot(%p0, %p1) // 矩阵乘法
  
  // 复杂的广播过程
  %reshape.7 = f32[1,64] reshape(%p2)
  %broadcast.8 = f32[1,64] broadcast(%reshape.7), dimensions={0,1}
  %reshape.9 = f32[64] reshape(%broadcast.8)
  %broadcast.10 = f32[10,64] broadcast(%reshape.9), dimensions={1}
  
  %add.11 = f32[10,64] add(%dot.6, %broadcast.10)
  %constant.5 = f32[] constant(0)
  %broadcast.12 = f32[10,64] broadcast(%constant.5), dimensions={}
  ROOT %maximum.12 = f32[10,64] maximum(%add.11, %broadcast.12)  // ReLU
}
```

#### 优化后（简化 HLO）：
```
ENTRY main {
  %p0 = f32[10,32]{1,0} parameter(0)
  %p1 = f32[32,64]{1,0} parameter(1)
  %dot.6 = f32[10,64]{1,0} dot(%p0, %p1)
  
  %fusion.1 = f32[10,64] fusion(%dot.6, %p2), kind=kLoop, calls={
    // 融合计算：直接广播 + 加法 + ReLU
    %broadcast.2 = f32[10,64] broadcast(%Arg_1.3), dimensions={1}
    %add.0 = f32[10,64] add(%Arg_0.2, %broadcast.2)
    ROOT %maximum.0 = f32[10,64] maximum(%add.0, %constant)
  }
  ROOT %tuple = (f32[10,64]) tuple(%fusion.1)
}
```

### 8.3 发生的优化类型

| 优化类型 | 优化前 | 优化后 | 作用 |
|----------|--------|--------|------|
| **广播简化** | 多步 reshape+broadcast | 一步 broadcast | 减少中间张量创建 |
| **操作融合** | add、maximum 独立执行 | 融合到 fused_computation | 减少内存读写 |
| **常量传播** | 分离的 constant+broadcast | 内联到 fusion | 简化计算图 |

### 8.4 为什么融合 add 和 maximum 而不融合 dot？

**融合原则**：
- 融合旨在减少内存访问、内核调用，提高并行性
- XLA 只融合"兼容"的操作

**融合 add 和 maximum 的原因**：
- 都是元素级操作，每个元素独立计算
- 数据依赖链清晰（add → maximum）
- 融合后可生成紧凑的 SIMD 向量化代码

**不融合 dot 的原因**：
- dot 是计算密集型操作，有专用优化（BLAS 库）
- 融合可能破坏内存布局优化
- 成本模型评估：融合收益小，编译复杂度增加

### 8.5 元素级操作详解

元素级操作是指对张量中每个元素独立执行的运算：

| 操作 | 示例 | 说明 |
|------|------|------|
| add | `a + b` | 对应元素相加 |
| maximum | `max(a, b)` | 对应元素取大 |
| multiply | `a * b` | 对应元素相乘 |
| exp | `exp(a)` | 指数运算 |

**非元素级操作示例**：
- dot（矩阵乘法）：涉及行/列的点积
- reduce（归约）：跨维度聚合
- convolution（卷积）：滑动窗口计算

## 九、性能分析工具使用

### 9.1 perf 工具使用

perf 是 Linux 系统级性能分析工具，用于量化 CPU 时间。

#### 基本用法：

```bash
# 记录性能数据
perf record -g -- python your_model.py

# 分析报告（交互式界面）
perf report

# 指定输出文件
perf record --output=perf_data.data -g -- python your_model.py

# 指定文件夹
perf record --output=/path/to/perf_data/run1.data -g -- python your_model.py
```

#### perf report 交互操作：

| 按键 | 功能 |
|------|------|
| 上下箭头 | 选择函数 |
| Enter | 查看调用图 |
| q | 退出 |
| / | 搜索函数 |
| s | 切换排序 |

#### 火焰图生成：

```bash
# 安装工具
sudo apt install flamegraph

# 生成火焰图
perf script | stackcollapse-perf.pl | flamegraph.pl > flamegraph.svg
```

### 9.2 XLA hlo_profile 使用

```bash
# 启用 HLO profiling
XLA_FLAGS="--xla_hlo_profile" python your_model.py

# 导出详细 profile
XLA_FLAGS="--xla_hlo_profile --xla_dump_hlo_profile=/path/to/profile.txt" python your_model.py
```

### 9.3 性能分析结果解读

**cycles:P (incl.) 参数含义**：
- `cycles`：CPU 周期数
- `P`：Percentage（百分比）
- `incl.`：inclusive（包含），表示该函数及其所有子调用的总占比

**火焰图阅读方法**：
- 横轴宽度：该函数及其子调用的 CPU 周期占比
- 纵轴高度：调用栈深度
- 颜色：仅用于区分函数，无特殊含义
