# XLA 工具链

XLA 开发工作流通常围绕 [HLO](./operation_semantics) IR 展开，它表示交给编译器的隔离功能计算。XLA 提供了多个命令行工具，这些工具消费 HLO 并运行它或提供中间编译阶段。使用这些工具对于快速的 `编译→修改→运行` 迭代周期非常有价值，因为 HLO 既可可视化又可修改。

获取正在用 XLA 编译的程序的 HLO 最简单的方法通常是使用 `XLA_FLAGS` 环境变量：

```
$ XLA_FLAGS=--xla_dump_to=/tmp/myfolder ./myprogram-entry-point
```

这会将所有预优化 HLO 文件存储到指定文件夹中，以及其他许多有用的工件。

## [`run_hlo_module`] 运行 HLO 模块

```
bazel run //xla/tools:run_hlo_module -- [flags] <filename>
```

`run_hlo_module` 工具操作预优化 HLO，默认捆绑编译、运行和与参考解释器实现比较。例如，在 NVIDIA GPU 上运行 `computation.hlo` 并检查正确性：

```
run_hlo_module --platform=CUDA --reference_platform=Interpreter computation.hlo
```

### 运行多个 HLO 模块

```
bazel run //xla/tools:run_hlo_module -- [flags] /dump/*before_optimizations*
```

## [`multihost_hlo_runner`] 运行带 SPMD 支持的 HLO 模块

```
bazel run //xla/tools/multihost_hlo_runner:hlo_runner_main -- [flags] <filename>
```

多主机 HLO 运行器类似，但额外支持 SPMD，包括跨主机通信。参见[多主机 HLO 运行器](./tools_multihost_hlo_runner)了解详情。

也可以不运行仅编译相同 HLO：

```
bazel run //xla/tools/multihost_hlo_runner:hlo_runner_main -- --run=false my-hlo.txt
```

## [`hlo-opt`] 编译 HLO 模块

```
bazel run //xla/tools:hlo-opt -- --platform=[gpu|cpu|...] [more flags] <filename>
```

`hlo-opt` 支持多个输出阶段：PTX、优化后的 HLO、优化前后的 LLVM IR 或 TritonIR。支持的阶段集取决于平台。使用 `--list-stages` 查看：

```
hlo-opt --platform=CUDA --list-stages
buffer-assignment
hlo
hlo-backend
html
llvm
llvm-after-optimizations
llvm-before-optimizations
ptx
```

选择阶段后，可以将结果写入给定流：

```
hlo-opt --platform=cpu --stage=hlo input.hlo
```

### GPU 无设备编译

无设备编译不需要访问 GPU。通过命令行指定 GPU 规格 (`--xla_gpu_target_config_filename`) 来消除对 GPU 设备的需求。

```
hlo-opt --platform=CUDA --stage=llvm --xla_gpu_target_config_filename=/xla/tools/hlo_opt/gpu_specs/a100_pcie_80.txtpb input.hlo
```

流行 GPU 的规格随编译器一起提供。GPU 规格文件是 `device_description.proto` 的字符串序列化，包含 CUDA 计算能力、线程限制、内存带宽、时钟频率等信息。

#### 自动调优

无设备编译需要禁用自动调优 (`--xla_gpu_autotune_level=0`) 或加载预存的自动调优结果 (`--xla_gpu_load_autotune_results_from=<filename>`)。

自动调优数据库可以通过 `XLA_FLAGS=--xla_gpu_dump_autotune_results_to=<myfile.pbtxt>` 序列化。

## [`hlo-opt`] HLO Pass 开发与调试

```
# 如果使用 xla/hlo/transforms/ 中的硬件无关 Pass，使用轻量版本：
bazel run //xla/hlo/tools:hlo-opt -- [flags] <filename>

# 否则使用完整的 hlo-opt：
bazel run //xla/tools:hlo-opt -- [flags] <filename>
```

`hlo-opt` 工具允许独立于给定平台编译阶段执行单个 Pass。这种隔离有助于在输入 HLO 模块上快速运行 Pass 并定位失败的根本原因。

```
hlo-opt --passes=schedule-aware-collective-cse input.hlo
```

注意：不需要 `--platform` 选项。`hlo-opt` 也支持 [`DebugOptions XLA_FLAGS`](https://github.com/openxla/xla/blob/main/xla/xla.proto)。

使用 `--list-passes` 获取 Pass 名称字符串。用户可以创建自定义流水线：

```
hlo-opt --passes=pass1,pass2,pass3 input.hlo
```

### 辅助新 HLO Pass 开发

1. 编写您的 Pass
2. 将新 Pass 注册到 `hlo-opt` Pass 注册表：
   ```
   RegisterPass<FooPass>(FooPassInputOptions)
   ```
   根据 Pass 类型选择注册位置：
   - `opt_lib.cc`：硬件无关 Pass
   - `cpu_opt.cc`：CPU 特定 Pass
   - `gpu_opt.cc`：GPU 特定 Pass
   - `compiled_opt_lib.cc`：CPU、GPU、XPU 通用 Pass
3. 重新构建 `hlo-opt`，使用 `--list-passes` 验证注册，然后使用 `--passes` 运行 Pass
4. 编写单元测试，参阅[测试 HLO Pass](https://openxla.org/xla/test_hlo_passes)

### Pass 运行时测量

对于大型模型，完整编译运行可能需要几分钟，因此难以检测细微的性能回退。使用 `hlo-opt` 的单独 Pass 运行允许精确的性能测量：

```
time hlo-opt --passes=reduce-window-rewriter,scatter_simplifier \
  --xla_reduce_window_rewrite_base_length=128 input.hlo
```

## [`hlo-opt`] HLO 模块格式转换

#### 转换 `HLO Text` → `HLO Proto`

```
hlo-opt --emit-proto input.hlo
```

#### 转换 `HLO Proto` 或 `HLO Proto Binary` → `HLO Text`

```
hlo-opt input.pbtxt or input.pb
```
