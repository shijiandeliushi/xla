# 形状与布局

XLA 的 `ShapeProto` protobuf（定义在 [xla_data.proto](https://github.com/openxla/xla/tree/main/xla/xla_data.proto) 中）描述了一个 N 维数组（下简称 *数组*）的维度数、各维度大小以及数据类型。

## 术语、记法与约定

> 注意：在以往，XLA 曾使用 "rank" 一词来表示数组的维度数。由于这和线性代数中矩阵的"秩 (rank)"概念不一致，我们已停止这种用法。但是，您仍然可能在旧文档和部分代码中看到 `rank` 被用来表示"维度数"。

* 数组的 *实际维度数* 是指大小大于 1 的维度个数。

* 对于一个 `N` 维数组，维度的编号从 `0` 一直到 `N-1`。维度的大小是一个非负整数。特别地，大小为 0 是合法的。维度编号只是为了方便而设的任意标签，其顺序并不暗示形状在布局中的 minor/major 顺序。布局由 `LayoutProto` protobuf 决定。

* 按照惯例，维度按各自的编号升序排列。例如，对于一个大小为 `[A x B x C]` 的 3 维数组，维度 0 的大小为 `A`，维度 1 的大小为 `B`，维度 2 的大小为 `C`。

    XLA 中的某些工具函数也支持类 Python 风格的负索引：维度 -1 表示最后一个维度（对 `N` 维数组等价于 `N-1`）。例如，对于上述 3 维数组，维度 -1 的大小为 `C`，维度 -2 的大小为 `B`，依此类推。

* 二维、三维和四维数组通常有特定的字母与维度对应。例如，对于二维数组：
    * 维度 0：`y`
    * 维度 1：`x`
    
    对于三维数组：
    * 维度 0：`z`
    * 维度 1：`y`
    * 维度 2：`x`
    
    对于四维数组：
    * 维度 0：`p`
    * 维度 1：`z`
    * 维度 2：`y`
    * 维度 3：`x`

* XLA API 中接受维度的函数均按维度编号的升序来使用这些维度，这与使用 `initializer_list` 传递维度时的顺序一致，例如：

    `ShapeUtil::MakeShape(F32, {A, B, C, D})`

    将创建一个维度大小数组为 `[A, B, C, D]` 的形状。

## 布局

`LayoutProto` protobuf 描述了数组在内存中的表示方式，包含以下字段：

```
message LayoutProto {
  repeated int64 minor_to_major;
  int64 tail_padding_alignment_in_elements;
  ...
}
```

### Minor-to-major 维度顺序

唯一必填字段是 `minor_to_major`。该字段描述了形状中各个维度的 minor-to-major 顺序。`minor_to_major` 中的值是对该数组维度（对 `N` 维数组为 `0` 到 `N-1`）的一个排列，其中第一个值是 **最内层 (most-minor) 维度**，最后一个值是 **最外层 (most-major) 维度**。最内层维度指的是按线性内存顺序遍历数组元素时变化最频繁的那个维度。

例如，考虑如下大小为 `[2 x 3]` 的二维数组：

```
a b c
d e f
```

此处维度 `0` 大小为 2，维度 `1` 大小为 3。如果布局中的 `minor_to_major` 字段为 `[0, 1]`，则维度 `0` 为最内层维度，维度 `1` 为最外层维度，对应的线性内存布局为：

```
a d b e c f
```

这种 `0` 到 `N-1` 的 minor-to-major 顺序类似 *列优先 (column-major)*（对二维而言）。在代码中，假设维度是单调排列的，我们也可以称这种布局为 "dim 0 is minor"。

反之，如果布局中的 `minor_to_major` 字段为 `[1, 0]`，则线性内存布局为：

```
a b c d e f
```

对于 `N` 维数组，从 `N-1` 到 `0` 的 minor-to-major 顺序类似 *行优先 (row-major)*（对二维而言）。在代码中，假设维度是单调排列的，我们也可以称这种布局为 "dim 0 is major"。

#### 默认 minor-to-major 顺序

新创建的 Shape 的默认布局是"维度顺序为 major-to-minor"（即 `[N-1, ..., 0]`）。

### 填充

`tail_padding_alignment_in_elements` 字段定义了[分块](tiled_layout.md)数组在大小的对齐要求（以元素个数为单位）。在应用分块之后，将在布局的末尾添加填充元素，直到总元素数是该值的整数倍。

### 对数组进行索引

`IndexUtil` 类（在 [index_util.h](https://github.com/openxla/xla/tree/main/xla/index_util.h) 中）提供了在给定形状和布局的情况下，在多维索引和线性索引之间进行转换的工具函数。多维索引对每个维度包含一个 `int64` 索引，而线性索引是一个单一的 `int64` 值，用于在存储数组的缓冲区中进行定位。另请参考同一目录下的 `shape_util.h` 和 `layout_util.h`，它们提供了简化形状和布局的创建与操作的工具函数。
