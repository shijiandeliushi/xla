# 分块布局 (Tiled Layout)

> **注意：** 分块布局处于*预发布*阶段，本文描述其预期工作方式。错误可能被静默忽略。

分块布局描述了数组在内存中如何通过分块的方式排列。一个带有这种布局的形状写作 `F32[3,5]{1,0:T(2,2)}`，其中 `1,0` 与物理维度顺序相关（Layout 中的 `minor_to_major` 字段），而冒号后的 `(2,2)` 表示按 2x2 块对物理维度进行分块。

直观上，块被排列以覆盖整个形状，然后在每个块内，元素按无分块的方式排列。为了在原始数组边界不完整时拥有完整的 2x2 块，会添加白色填充元素。填充中的额外元素不需要包含任何特定值。

## 给定形状和块的线性索引公式

无分块时，元素 e=(e_n, e_{n-1}, ..., e_1) 在数组边界 d=(d_n, d_{n-1}, ..., d_1)（d_1 是最小维度）中按主到次顺序排列在位置：

&nbsp;&nbsp; linear_index(e, d) = e_n·d_{n-1}...d_1 + e_{n-1}·d_{n-2}...d_1 + ... + e_1

使用大小为 (t_n, t_{n-1}, ..., t_1) 的分块时，数组中索引为 (e_n, e_{n-1}, ..., e_1) 的元素映射到最终布局中的位置：

&nbsp;&nbsp; linear_index_with_tile(e, d, t)
= linear_index((⌊e/t⌋, e mod t), (⌈d/t⌉, t))

布局可以认为有两个部分：
- (⌊e_n/t_n⌋, ..., ⌊e_1/t_1⌋)：在大小为 (⌈d_n/t_n⌉, ..., ⌈d_1/t_1⌉) 的块数组中的块索引
- (e_n mod t_n, ..., e_1 mod t_1)：块内索引

ceil 函数出现在 ⌈d_i/t_i⌉ 中，因为如果块超出较大数组的边界，会插入填充。块和块内元素都按无分块方式递归排列。

## 分块作为 pad-reshape-transpose

基于分块的布局可以描述为以下 pad-reshape-transpose 操作：

1. 数组被填充到 (⌈d_n/t_n⌉·t_n, ..., ⌈d_1/t_1⌉·t_1)
2. 每个维度 i 被拆分为 (⌈d_i/t_i⌉, t_i)，即数组被 reshape。这个 reshape 本身没有物理布局改变，所以是一个 bitcast
3. 执行 transpose，将 t_n, ..., t_1 移动到最次要维度，同时保持它们的相对顺序

最终形状的前缀 (⌈d_n/t_n⌉, ..., ⌈d_1/t_1⌉) 描述了每个维度中的块数。

## 重复分块

XLA 的分块通过重复应用变得更加灵活。例如 `(2,4)(2,1)` 表示先 2x4 再 2x1。这种格式匹配 TPU 上用于 BF16 的格式，只是初始块更大，即分块为 `(8,128)(2,1)`，其中第二次 2x1 分块的目的是将两个 16 位值收集在一起形成一个 32 位值，以与 TPU 架构对齐。

## 使用块组合维度

XLA 的分块还支持组合维度。例如，可以将 `F32[2,7,8,11,10]{4,3,2,1,0}` 中的维度组合成 `F32[112,110]{1,0}`，然后用 `(2,3)` 分块。使用的块是 `(*,*,2,*,3)`，其中星号表示将该维度与下一个更次要维度组合。多个相邻维度可以合并为一个维度。被合并的维度在块的该维度中用值 -1 表示。
