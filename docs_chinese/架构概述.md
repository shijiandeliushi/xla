# XLA 架构

XLA（加速线性代数）是一个专门优化线性代数的机器学习 (ML) 编译器，能够在执行速度和内存使用方面提供显著的改进。本页面简要概述了 XLA 编译器的设计目标与架构。

## 目标

目前，XLA 支持多种 ML 框架前端（包括 PyTorch、TensorFlow 和 JAX），并且是 OpenXLA 项目的一部分——OpenXLA 是一个由领先的 ML 硬件和软件组织共同开发的、面向开源编译器技术的生态系统。在 OpenXLA 项目成立之前，XLA 是在 TensorFlow 项目内部开发的，但其基本目标至今保持不变：

* **提高执行速度**：通过编译子图减少短生命周期 Op 的执行时间并消除运行时开销；融合流水线化的操作以减少内存开销；对已知的张量形状进行特化以实现更激进的常量传播。

* **改善内存使用**：分析和调度内存使用，消除大量中间存储缓冲区。

* **减少对自定义 Op 的依赖**：通过提升自动融合的低级 Op 的性能，使之达到最初由手动融合的自定义 Op 的性能水平，从而减少对大量自定义 Op 的需求。

* **提高可移植性**：使为新型硬件编写新后端变得相对容易，从而让大部分 ML 模型可以不经修改就在该硬件上运行。这与针对每个新型硬件特化单个巨型 Op 的方法形成对比——那种方法需要重写模型才能使用这些 Op。

## 工作原理

XLA 编译器从 ML 框架获取以 [StableHLO](https://github.com/openxla/stablehlo) 定义的模型图，并将其编译为适用于各种架构的机器指令。StableHLO 定义了一套版本化的操作集（HLO = 高级操作），在 ML 框架和编译器之间提供了一个可移植层。

将模型图转换为针对目标优化的可执行文件的编译过程一般包括以下步骤：

1. XLA 对 StableHLO 图执行若干内建的、与目标无关的优化和分析 Pass，例如 [CSE（公共子表达式消除）](https://en.wikipedia.org/wiki/Common_subexpression_elimination)、与目标无关的操作融合，以及为计算分配运行时内存的缓冲区分析。在此优化阶段，XLA 还会将 StableHLO dialect 转换为内部的 HLO dialect。

2. XLA 将 HLO 计算体发送到后端，进行进一步的 HLO 级别优化——此阶段需要考虑特定目标的信息和需求。例如，GPU 后端可能会执行特别有利于 GPU 编程模型的操作融合，并确定如何将计算分区到不同的流中。在此阶段，后端也可以将某些操作或操作组合模式匹配为优化过的库调用。

3. 后端随后执行针对特定目标的代码生成。XLA 自带的 CPU 和 GPU 后端使用 [LLVM](http://llvm.org) 进行低级别 IR 的生成、优化和代码生成。这些后端高效地生成表示 HLO 计算的 LLVM IR，然后调用 LLVM 从此 LLVM IR 生成本机代码。

在此过程中，XLA 编译器是模块化的：可以很容易地插入一个替代后端来[针对某种新型硬件架构](./开发新后端.md)。GPU 后端目前通过 LLVM NVPTX 后端支持 NVIDIA GPU。CPU 后端则支持多种 CPU ISA。
