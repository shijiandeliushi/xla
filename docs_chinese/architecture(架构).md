# XLA 架构

XLA（加速线性代数，Accelerated Linear Algebra）是一个针对线性代数进行优化的机器学习（ML）编译器，能够提升执行速度和内存使用效率。本文简要概述了 XLA 编译器的目标和架构。

## 目标

如今，XLA 支持多种 ML 框架前端（包括 PyTorch、TensorFlow 和 JAX），并且是 OpenXLA 项目的一部分——这是一个由领先的 ML 硬件和软件组织协作开发的开源编译器技术生态系统，用于 ML。在 OpenXLA 项目创建之前，XLA 是在 TensorFlow 项目内部开发的，但其基本目标保持不变：

*   **提升执行速度。** 编译子图以减少短期运行操作（op）的执行时间并消除运行时开销；融合流水线操作以减少内存开销；针对已知张量形状进行特化，以实现更积极的基本常量传播。

*   **改善内存使用。** 分析和调度内存使用，消除许多中间存储缓冲区。

*   **减少对自定义操作的依赖。** 通过提升自动融合的低级操作的性能，使其与原先手工融合的自定义操作性能相匹配，从而消除对许多自定义操作的需求。

*   **提升可移植性。** 使得为新型硬件编写新后端相对容易，从而使大部分 ML 模型能够在该硬件上无需修改地运行。这与为新型硬件特化单个 monolithic 操作的方法形成对比，后者需要重写模型才能利用这些操作。

## 工作原理

XLA 编译器接收来自 ML 框架的、以[StableHLO](https://github.com/openxla/stablehlo)定义的模型图，并将其编译为适用于各种架构的机器指令。StableHLO 定义了一套带版本控制的操作集（HLO = 高级操作，high level operations），为 ML 框架和编译器之间提供了可移植性层。

通常，将模型图转换为目标优化后的可执行文件的编译过程包括以下步骤：

1.  XLA 对 StableHLO 图执行若干内置的、与目标无关的优化和分析过程，例如
[CSE](https://en.wikipedia.org/wiki/Common_subexpression_elimination)（公共子表达式消除）、与目标无关的操作融合以及用于为计算分配运行时内存的缓冲区分析。在此优化阶段，XLA 还会将 StableHLO 方言（dialect）转换为内部 HLO 方言。

2.  XLA 将 HLO 计算发送给后端，以进行进一步的 HLO 级优化，这次会考虑特定于目标的信息和需求。例如，GPU 后端可能会执行对 GPU 编程模型特别有益的操作融合，并决定如何将计算划分到不同的流中。在此阶段，后端还可能将某些操作或操作组合与优化的库调用进行模式匹配。

3.  然后，后端执行特定于目标的代码生成。XLA 自带的 CPU 和 GPU 后端使用[LLVM](http://llvm.org)进行低级 IR、优化和代码生成。这些后端发出必要的 LLVM IR，以高效的方式表示 HLO 计算，然后调用 LLVM 从该 LLVM IR 生成本地代码。

在这个过程中，XLA 编译器是模块化的，可以轻松地插入替代后端以[针对某些新颖的硬件架构](./developing_new_backend.md)。GPU 后端目前通过 LLVM NVPTX 后端支持 NVIDIA GPU。CPU 后端支持多种 CPU ISA。
