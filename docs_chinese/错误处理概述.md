# XLA 错误处理概述

XLA 的错误根据不同的 XLA 错误来源进行分类。每个来源除了错误消息之外，还会附加一些额外的上下文信息，这些信息将被附加到该分类下的每个错误中。

> 注意：该标准化工作仍在进行中，因此并非所有错误消息都已有附加的错误代码。

一个错误日志示例可能如下所示：

```
XlaRuntimeError: RESOURCE_EXHAUSTED: XLA:TPU compile permanent error.
Ran out of memory in memory space hbm. Used 49.34G of 32.00G hbm.
Exceeded hbm capacity by 17.34G.

JaxRuntimeError: RESOURCE_EXHAUSTED: Ran out of memory in memory space vmem
while allocating on stack for ...
```

## Status 与 CHECK 失败

在 XLA 中，有两种标记执行异常的主要机制：Status 和 CHECK 宏失败。

- **Status** 用于非致命的、可恢复的错误。设计假设是函数返回后，调用方显式检查返回的 Status 对象，执行继续。适用于处理无效的用户输入或预期的资源约束。

- **CHECK 失败** 则涵盖程序员错误或违反了那些"如果代码正确就永远不会发生"的不变量。当 CHECK 被触发时，程序将记录错误消息并立即终止。它用于确保内部一致性，比如在解引用之前检查指针是否非空。
