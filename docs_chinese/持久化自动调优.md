# 持久化自动调优（仅 GPU）

我们使用 OpenAI Triton 生成部分 GPU 内核。Triton 可以为某些融合生成快速的 GPU 内核，但我们需要为每个这样的融合调优一些参数。

如果融合很多，这可能花费很长时间，因此我们提供了一种方式来加载这些自动调优结果，同时仍正常运行其他编译步骤。自动调优缓存在我们做少量更改时仍然有用：缓存中存在的融合将使用缓存，其他融合将正常进行自动调优。

## 推荐：缓存目录

```
--xla_gpu_per_fusion_autotune_cache_dir=your/directory
```

在给定目录中使用和维护每个融合的自动调优缓存。每个不同的融合将有一个文件。

此方法的主要优点是可以为多个 XLA 运行（不同模型）使用相同的缓存目录，并且缓存会随着遇到的每个新融合而增长——加速后续运行。还支持多个 XLA 实例同时使用相同缓存目录的基本并发支持。

XLA 将在需要时读取现有结果，并在确定新结果后写入它们。

- 目录必须在运行 XLA 之前存在且可写
- 缓存失效必须由用户处理（使用空目录以从空缓存开始）
- XLA 版本检查必须由用户完成（为不同版本的 XLA 使用不同的目录）

默认情况下缓存是关闭的（不提供参数时）。

## 替代方案：将给定 HLO 的所有结果加载或转储到一个文件

```
--xla_gpu_dump_autotune_results_to=
--xla_gpu_load_autotune_results_from=
```

如果指定 .txt 或 .textproto 文件，缓存将以 textproto 格式转储，否则以二进制 protobuf 格式转储。

## 在测试中使用

持久化自动调优也可用于测试。如果测试非常大，尤其是在测试环境性能有限的情况下，建议使用它。

仅在自动调优缓存包含在与运行测试相同类型的 GPU 上生成的结果时才有效。

### 使测试使用持久化自动调优

1. 从测试导出自动调优结果：
   ```
   --test_env=XLA_FLAGS=--xla_gpu_dump_autotune_results_to=TEST_UNDECLARED_OUTPUTS_DIR/autotune_cache.textproto
   --test_sharding_strategy=disabled
   ```
   必须禁用分片以正确获取所有测试的单个自动调优缓存。

2. 将该缓存上传到代码仓库。

3. 将缓存添加到测试目标的 data 依赖项，并使用环境变量加载：
   ```
   data = ["test_autotune_cache.textproto"],
   env = {"XLA_FLAGS": "--xla_gpu_load_autotune_results_from=" +
                       "$(execpath test_autotune_cache.textproto)"},
   ```

### 缓存过时

如果对模型进行了许多更改，缓存可能不再包含所有融合，因此测试将变得更慢。在这种情况下，需要重新生成自动调优缓存。如果开始使用新型 GPU 运行测试，同样适用。当 XLA 编译器演进并生成不同的融合时，缓存也可能过时。
