# 索引分析 (Indexing Analysis)

HLO 索引分析是一种[数据流分析](https://en.wikipedia.org/wiki/Data-flow_analysis)，通过"索引映射"描述一个张量的元素如何关联到另一个张量。例如，HLO 指令输出的索引如何映射到 HLO 指令操作数的索引。

## 示例

对于从 `tensor<20xf32>` 到 `tensor<10x20x30xf32>` 的广播：

```c
p0 = f32[20] parameter(0)
bc0 = f32[10, 20, 30] broadcast(p0), dimensions={1}
```

从输出到输入的索引映射为 `(i, j, k) -> (j)`，其中 `i in [0, 10]`，`j in [0, 20]`，`k in [0, 30]`。

## 动机

XLA 使用多种定制方案来推理合并访问、操作数利用率和分块方案。索引分析的目标是为这些用例提供可复用的组件，建立在 MLIR 的 Affine Map 基础设施之上并增加 HLO 语义。

### 合并访问 (Coalescing)
当我们知道读取输入中的哪些元素/切片来计算输出的一个元素时，可以推理非平凡情况下的内存合并。

### 操作数利用率 (Operand Utilization)
指示假设指令输出被完全使用时，每个输入被使用的程度。索引分析允许精确计算利用率。

### 分块 (Tiling)
分块/切片是张量的超矩形子集，由偏移、大小和步长参数化。分块传播是一种使用操作本身的分块参数来计算操作的生产者/消费者的分块参数的方法。通过索引映射表达分块传播可以更加通用和健壮。

## 索引映射 (Indexing Map)

索引映射是以下内容的组合：
- 一个符号化表达的函数，将张量 `A` 的每个元素映射到张量 `B` 中的元素范围
- 对有效函数参数（包括函数定义域）的约束

函数参数分为 3 类：
- **维度变量 (dimension variables)**：张量 `A` 或 GPU 网格的维度；值在静态已知
- **范围变量 (range variables)**：定义一对多映射，指定 `B` 中用于计算 `A` 单个值的元素集合；例如矩阵乘法的收缩维度
- **运行时变量 (runtime variables)**：仅在执行时已知的值；例如 gather 操作的 indices 参数

简而言之，从张量 `A` 到张量 `B` 对于操作 `x` 的索引函数是：

`map_ab(A中的索引, 范围变量, 运行时变量) -> B中的索引`

更好的写法为：

`map_ab(A中的索引)[范围变量]{运行时变量} -> (B中的索引)`

## 实现

由于我们希望最小化重复计算，我们需要一个符号计算库。XLA 已依赖 MLIR，因此使用 [mlir::AffineMap](https://github.com/llvm/llvm-project/blob/main/mlir/include/mlir/IR/AffineMap.h)。

典型的 `AffineMap` 形式：
```
(d0)[s0, s1] -> (s0 + 5, d0 * 2, s1 * 3 + 50)
```

`AffineMap` 有两种参数：*dimensions* 和 *symbols*。*Dimensions* 对应维度变量 *d*；*symbols* 对应范围变量 *r* 和运行时变量 *rt*。

核心数据结构 `IndexingMap`：
```c
class IndexingMap {
  mlir::AffineMap affine_map_;
  std::vector<Variable> dim_vars_;    // 维度变量及其区间约束
  std::vector<Variable> range_vars_;  // 范围变量
  std::vector<Variable> rt_vars_;     // 运行时变量
  llvm::DenseMap<mlir::AffineExpr, Interval> constraints_; // 附加约束
};
```

## 常见操作的索引映射

### 逐元素操作 (Elementwise)
索引映射是恒等映射：`(d0, d1) -> (d0, d1)`，定义域由输出形状决定。

### 广播 (Broadcast)
输入到输出的映射引入了范围变量。例如 `f32[20]` → `f32[10,20,30]`，dimensions={1}：
- 输出→输入：`(d0, d1, d2) -> (d1)`
- 输入→输出：`(d0)[s0, s1] -> (s0, d0, s1)`

### Transpose
索引映射是维度排列。例如 `f32[3,12288,6,128]` → `f32[3,6,128,12288]`，dimensions={0,2,3,1}：
- 输出→输入：`(d0, d1, d2, d3) -> (d0, d3, d1, d2)`

### Reduce
归约引入了范围变量。例如 `f32[256,10]` reduce on dim=0 → `f32[10]`：
- 输出→输入：`(d0)[s0] -> (s0, d0)`，其中 s0 in [0, 255]

### Reshape
折叠形状（Collapse）：`f32[4,8]` → `f32[32]`：
- 输出→输入：`(d0) -> (d0 floordiv 8, d0 mod 8)`

展开形状（Expand）：`f32[32]` → `f32[4,8]`：
- 输出→输入：`(d0, d1) -> (d0 * 8 + d1)`

通用 Reshape 可以表示为展开和折叠的组合。

### 融合 (Fusion)
融合操作的索引映射是聚类中每个操作的索引映射的组合。某些输入可能以不同的访问模式被多次读取。

## 索引映射简化器

由于上游默认的 `mlir::AffineMap` 简化器无法对维度/符号的范围做出假设，因此无法有效简化包含 `mod` 和 `div` 的表达式。

我们可以利用仿射映射中子表达式下界和上界的知识来进一步简化它们。例如：
- `(d0, d1) -> (d0 + d1 floordiv 16, d1 mod 16)` 当 d0 in [0,6], d1 in [0,14] 时简化为 `(d0, d1) -> (d0, d1)`

这使得我们能够理解 HLO 中的一些链式 reshape 会互相抵消。
